1. Create cohort

Vagish Hemmige

This script builds the cohort of kidney transplant recipients with a cryptococcosis claim after their first transplant and Medicare primary coverage before it, records each exclusion in a flowchart, and attaches residence and transplant-center information for later scripts.

The full R script is available at:

  • R/create_cohort.R

This R script file is itself reliant on the following helper file:

  • R/setup.R

The code sections below are imported directly from that script when this page is rendered.

Every inclusion and exclusion goes through fc_filter() from the flowchart package, so the cohort flow diagram drawn on the Figures page reproduces the cohort exactly. The cohort used downstream is patients_fc$data after the last step.

Load the patient file

The USRDS patients file supplies one row per person with demographics and transplant summary fields, loaded through usRds::load_usrds_file(). Its ZIP code is dropped here because it is the ZIP code when the person entered USRDS; the analysis needs residence at the time of the cryptococcosis claim, which is attached in the last step.

#Import core demographics from "patients" file
patients_raw<-usRds::load_usrds_file("patients")%>%
  select(-ZIPCODE) #This is ZIP code at time of USRDS initiation, but we want at time of crypto dx

Start the flowchart

The patient file becomes a flowchart object, and the first step keeps people with at least one recorded transplant (TOTTX > 0).

Click to show/hide R Code 
#Initialize a flowchart cohort and remove patients who have never had a transplant
patients_fc<-patients_raw%>%
  as_fc(label="Initial USRDS cohort")%>%

  fc_filter(TOTTX>0,
            label="Prior transplant",
            label_exc="Excluded: No prior transplant",
            show_exc=TRUE)

Find cryptococcosis claims

For the people still in the cohort, get_IN_ICD() and get_PS_ICD() from usRds search the institutional and physician/supplier claims of the years in claim_years for the codes in cryptococcus_ICD_list (see Setup). The two sets are stacked, and each person’s earliest claim of any type, by claim start date, is kept as first_cryptococcus_date.

Section 3 of the analysis plan specifies a confirmed case (one inpatient stay, or two noninpatient encounters no more than 30 days apart), an index date within the qualifying episode, a uniform prior-history exclusion, and excludes skilled nursing, home health and hospice claims from ascertainment (section 2). The current code uses the first single claim and does not yet apply those rules.

#Create list of USRDS ids for patients who have undergone transplant
transplant_id_list<-patients_fc$data%>%
  pull(USRDS_ID)

#Obtain cryptococcus claims from the IN and PS files
cryptococcus_claims_df<-bind_rows(get_IN_ICD(icd_codes = cryptococcus_ICD_list,
                                             years = claim_years,
                                             usrds_ids = transplant_id_list),
                                  get_PS_ICD(icd_codes = cryptococcus_ICD_list,
                                             years = claim_years,
                                             usrds_ids = transplant_id_list)%>%
                                    rename(CODE=DIAG))

#Keep the first cryptococcus claim of any type for each patient
cryptococcus_df<-cryptococcus_claims_df%>%
  slice_min(CLM_FROM, n = 1, with_ties = FALSE, by = USRDS_ID)%>%
  select(USRDS_ID, first_cryptococcus_date=CLM_FROM)

Apply the claim and transplant-timing steps

The first claim date is joined to the cohort one-to-one by USRDS_ID. Two flowchart steps follow: people with no cryptococcosis claim in the search years are excluded, and so are people whose first claim is not after their first transplant date (TX1DATE). The plan requires a kidney transplant strictly before the index date (section 4).

Click to show/hide R Code 
#Join cryptococcus date to fc cohort (one row per patient on both sides)
patients_fc$data<-patients_fc$data%>%
  left_join(cryptococcus_df,
            by = "USRDS_ID",
            relationship = "one-to-one")

patients_fc<-patients_fc%>%

  #Filter by whether or not the patient had a claim in the study period
  fc_filter(!is.na(first_cryptococcus_date),
            label="At least one cryptococcus claim 2006-2021",
            label_exc="No cryptococcus claim 2006-2021",
            show_exc=TRUE)%>%

  #Filter by whether or not the first claim was subsequent to the first kidney transplant date
  fc_filter(first_cryptococcus_date>TX1DATE,
            label="Cryptococcus subsequent to first transplant",
            label_exc="Excluded: Cryptococcus prior to first transplant",
            show_exc=TRUE)

Apply the Medicare coverage steps

usRds::verify_medicare_primary() adds the Medicare primary coverage spell in force on the first claim date, if any, and medicare_primary_TF, which is true when that spell began at least lookback_days earlier. A check stops the script if the coverage join produced more than one row for anyone. Two flowchart steps then keep people with Medicare primary coverage on the claim date, and people with coverage for the full lookback.

The plan’s primary cohort requires uninterrupted Medicare fee-for-service Parts A and B (MPAB) coverage from day −365 through day 0, with broader primary coverage (MPAB or MPO) as a sensitivity analysis (section 4). Which payer categories count as primary here is set by verify_medicare_primary(); see the usRds documentation.

Click to show/hide R Code 
#Mark Medicare FFS primary coverage on the date of the first cryptococcus claim, and whether
#that coverage spell began at least lookback_days earlier (adds medicare_primary_TF)
patients_fc$data<-patients_fc$data%>%
  verify_medicare_primary(index_date = "first_cryptococcus_date",
                          lookback_days = lookback_days,
                          coverage_start_variable = "coverage_start_date",
                          coverage_end_variable = "coverage_end_date")

#Confirm the coverage join did not duplicate patients
if (anyDuplicated(patients_fc$data$USRDS_ID) > 0) {
  stop("Medicare coverage join produced more than one row for some patients.")
}

patients_fc<-patients_fc%>%

  #Filter by Medicare primary coverage on day of claim
  fc_filter(!is.na(coverage_start_date),
            label="Medicare is primary coverage on date of claim",
            label_exc="Other coverage on date of claim",
            show_exc=TRUE)%>%

  #Filter by coverage for lookback_days before the claim
  fc_filter(medicare_primary_TF,
            label="365+ days of coverage prior to first cryptococcus claim",
            label_exc="Fewer than 365 days of coverage",
            show_exc=TRUE)

Attach residence and transplant center

The residenc file is joined to the cohort by an interval join, keeping the residence spell that contains the first claim date, and a check stops the script if that join duplicated anyone. The tx file is loaded with each transplant’s date, graft failure date, and center, and each transplant gets the date of the person’s next transplant (a far-future date when there is none), ready for choosing the transplant episode that precedes the index date. The facility file supplies each center’s ZIP code by year, matched to each transplant by center and the closest facility year at or after the transplant year.

These transplant and facility tables (transplant_df, transplant_joined) are built but not yet joined to the cohort. The plan uses the most recent kidney transplant before index for transplant characteristics and center (section 4).

Click to show/hide R Code 
#Load ZIP codes
ZIP_code_df<-load_usrds_file("residenc",
                             usrds_ids = patients_fc$data$USRDS_ID)%>%
  select(USRDS_ID, ZIPCODE, BEGRES, ENDRES)

#Join patient cohort to ZIP code at the date of the first cryptococcus claim
patients_fc$data<-left_join(patients_fc$data,
                            ZIP_code_df,
                            join_by(USRDS_ID, between(first_cryptococcus_date, BEGRES, ENDRES)))

#Confirm the residence join did not duplicate patients
if (anyDuplicated(patients_fc$data$USRDS_ID) > 0) {
  stop("Residence join produced more than one row for some patients.")
}

#Load transplant data, and add a date for the next transplant (missing set to 1-1-2100)
transplant_df<-load_usrds_file("tx", usrds_ids = patients_fc$data$USRDS_ID)%>%
  select(USRDS_ID, TDATE, FAILDATE, PROVUSRD, YEAR)%>%
  arrange(USRDS_ID, TDATE)%>%
  group_by(USRDS_ID)%>%
  mutate(TDATE_lead=lead(TDATE))%>%
  ungroup()%>%
  mutate(TDATE_lead=coalesce(TDATE_lead, as.Date("2100-01-01")))

#Load facility data
facility <- load_usrds_file("facility")%>%
  select(ZIPCODE, PROVUSRD, FS_YEAR)%>%
  rename(YEAR=FS_YEAR)%>%
  mutate(YEAR=as.double(YEAR))

#Interval merge
transplant_joined<-left_join(transplant_df, facility, join_by(PROVUSRD, closest(x$YEAR<=y$YEAR )))
